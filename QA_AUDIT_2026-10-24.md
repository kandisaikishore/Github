### QA execution policy

1. Detect stack and documented build/test commands for every repository.
2. Run available unit/component, API, integration, end-to-end, security/dependency, and build checks only where supported by repository configuration.
3. Record exact failing tests and logs; separate true defects from missing secrets/services or flaky infrastructure.
4. Implement narrowly scoped fixes on branches, add regression coverage, and rerun affected and full checks.
5. Do not merge or deploy automatically while checks are failing, missing, or not yet verified.

### Scope limitation

This first pass inspected concrete CI evidence and open PRs in selected repositories. It did not perform a full manual review or execute every test across all 53 repositories. Each repository needs an individual pass; projects whose tests depend on secrets, databases, browsers, or external services need those dependencies configured for meaningful verification.
